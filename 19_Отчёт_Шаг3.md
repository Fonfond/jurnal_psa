## 3. Аутентификация и CSRF

- `dev-login` проверяет `user_credentials` через `bcryptjs`, создаёт запись в `sessions` (opaque token, SHA-256), ставит `lb_session` (HttpOnly) и `lb_csrf` (читаемый) cookies.
- TTL сессии — `SESSION_TTL_DAYS` (30), `offline_valid_until` возвращается в `/me` и login.
- CSRF: double-submit, заголовок `X-CSRF-Token` обязателен для небезопасных методов; `dev-login` и OIDC-заглушки публичные.
- Guards: `AuthGuard` → `CsrfGuard` → `RolesGuard`.
- В production `dev-login` отключён; OIDC — `501` с `TODO(OQ-02)`.

## 4. Синхронизация и merge

### 4.1. Push

- Проверка владельца устройства, обновление `last_seen/app_version`.
- Идемпотентность: `idempotency_records` по `op_id`, ответ хранится 30 дней; повторный push возвращает `duplicate=true` и прежний результат.
- `version` назначает только сервер; `hlc` обновляется через `maxHlc`.
- Каждая операция — в транзакции: сущность + ревизия + `change_log` + аудит + idempotency.

### 4.2. Merge C-01…C-12

| Правило | Реализация |
|---|---|
| C-01 разные поля | да, полевое слияние |
| C-02 одно поле, два устройства | да, LWW по HLC |
| C-03 проверенная запись | да, правка автора блокируется |
| C-04 автор vs руководитель | да, LWW |
| C-05 удаление vs изменение | частично: сравнение HLC при несовпадении base_version |
| C-06 удаление/восстановление | частично: restore только admin |
| C-07 дубль `id` при create | частично: `E-VER-01`, без conflict_record |
| C-08 ручное время vs сервер | частично: HLC-порядок |
| C-09 аннулирование наряда | `TODO(OQ-03)` |
| C-10 merge в невалидное состояние | не проверяется после merge |
| C-11 сервер новее | `changes` применяет серверное состояние |
| C-12 два руководителя | да, HLC + серверный tie-break |

При конфликте создаётся `conflict_records` с `resolution='remote'`; проигравшее значение — в `entry_revisions`. `field_clocks` добавлены миграцией `0005_field_clocks.sql`.

### 4.3. Changes

- `seq > since_seq`, область видимости по роли, `limit ≤ 200`.
- Записи и наряды объединяются по `seq`; tombstones передаются как `op: delete`.
- `next_seq` — последний отданный `seq`; `has_more` учитывает лимиты обеих выборок.

## 8. Ограничения текущей реализации

1. Видимость нарядов для сотрудника — все не удалённые (`TODO(FR-PRM-11)`).
2. Экспорт создаёт задание в статусе `queued`, файл не формируется.
3. `GET /audit` без курсора; лимит 200.
4. Импорт CSV принимает содержимое в теле запроса, а не файл (`TODO`: upload).
5. `verify/unverify/restore` не создают `entry_revisions` (только аудит и `change_log`).
6. Админ создаёт пользователя без учётных данных — вход только после OIDC (`TODO(OQ-02)`).
7. Merge не проверяет итоговое состояние на валидность (C-10).
8. Проверка роли `auditor` — только чтение; отдельные ограничения v1.1.
