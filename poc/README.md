| Параметр | Значение |
|---|---|
| Назначение | Проверка гейтов G1 (ASR), G2 (IndexedDB), G3 (синхронизация) |
| Статус | Стенды исполняемые. Прогон 24.11.2026: **G1 — fail (blocked)**, **G2 — partial**, **G3 — pass (isolated prototype)**. Отчёт: `poc/report.md` |
| Связь | `12_План_PoC_Этап1.md`, `14_Стартовый_комплект_PoC.md`, `17_Чек-лист_приёмки_PoC_D10.md` |
| В поставку | **Не входит.** Архивируется и удаляется после отчёта PoC |

---

## 1. Жёсткие правила

1. Код в `poc/` не импортируется в продуктовый репозиторий и наоборот.
2. Никаких продуктовых схем БД, API-контрактов, аутентификации и UI-компонентов.
3. Никаких реальных ПДн, голосов без согласия, номеров нарядов.
4. Никакого деплоя, кроме локального стенда.
5. После отчёта PoC переносятся только выводы; код удаляется.

---

## 2. Структура

```
poc/
├── README.md
├── report.md        # отчёт по гейтам и ограничениям
├── g1/              # ASR harness: capture → chunker → asr adapter → metrics
├── g2/              # IndexedDB harness: schema, tx, export, migration, locks
├── g3/              # sync prototype: hlc, merge, change_log, idempotency, server
├── data/            # корпус, сиды, манифесты (синтетика)
├── results/         # CSV замеров и логи
└── tools/           # статический сервер, CDP-раннер, валидатор, манифест
```

Каталоги `g1/`, `g2/`, `g3/` содержат исполняемые стенды. `poc/tools/serve.mjs` — статический сервер для harness-страниц; `poc/tools/run-g1.mjs`, `run-g2.mjs` — прогоны в headless Edge; `poc/g3/run.mjs` — прогон G3 без браузера.

## 3. Локальный стенд

| Компонент | Адрес / порт |
|---|---|
| G1 harness | `http://127.0.0.1:8088/g1/harness.html` (запускается `run-g1.mjs`) |
| G2 harness | `http://127.0.0.1:8087/g2/harness.html` (запускается `run-g2.mjs`) |
| G3 API | `http://127.0.0.1:8081/poc/g3/health` |
| Результаты | `poc/results/*.csv` |

Порты 8087/8088 занимаются раннерами на время прогона; G3-сервер можно запустить отдельно на 8081.

## 5. Запрещено считать PoC продуктом

Прототип отвечает на вопрос «жизнеспособен ли подход», а не «готов ли продукт». Любая оптимизация прототипа, не влияющая на вывод гейта, не выполняется.
