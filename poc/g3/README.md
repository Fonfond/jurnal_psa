# G3 — прототип синхронизации и merge

| Параметр | Значение |
|---|---|
| Гейт | G3 (`12_План_PoC_Этап1.md`, раздел 7) |
| Статус | Исполняемый прототип; прогон 24.11.2026 — **pass** для изолированной модели (24 сценария, 560 строк) |
| В поставку | Не входит |

## 1. Минимальный API прототипа

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/poc/g3/push` | Батч операций, результаты по каждой |
| `GET` | `/poc/g3/changes?since_seq` | Изменения по `seq` |
| `GET` | `/poc/g3/health` | Готовность стенда |

Аутентификация, права и продуктовые модели отсутствуют.

## 2. Модули

| Модуль | Ответственность |
|---|---|
| `hlc.*` | Формат 13+5+8, `tick`, `merge`, детект дрейфа |
| `merge.*` | C-01…C-12, приоритет роли, сохранение проигравшего |
| `change_log.*` | `seq`, страницы, `has_more` |
| `idempotency.*` | `op_id` → сохранённый ответ, TTL |
| `batch.*` | Порядок операций одной сущности |
| `server.*` | HTTP, in-memory или PostgreSQL |
| `scenarios.*` | 24 кейса POC-G3-01…24 |

## 3. Инварианты

1. Ни одна операция не теряется и не дублируется.
2. Результат merge детерминирован при одинаковом входе.
3. HLC-строки сравниваются лексикографически корректно.
4. `change_log.seq` без пропусков.
5. Все операции одной сущности применяются по порядку.
6. Повтор `op_id` возвращает прежний результат.

## 4. Ограничения

- Только синтетические данные и тестовая модель.
- Нет аутентификации, ролей, UI, деплоя.
- Прототип не является основой продуктового кода; переносятся только выводы.

## 5. Запуск и результат

```powershell
node poc/g3/run.mjs
```

Прогон 24.11.2026: 24 сценария, 560 строк, все детерминированы, `data_loss=false`; HLC/seq/идемпотентность/батчи без ошибок; HTTP 50 ops p95 = 5,26 мс. Вердикт G3 — pass для изолированного прототипа; продуктовая приёмка на PostgreSQL/транспорте — отдельно.
