# Logbook — сценарий презентации (5–7 минут)

## Перед показом

```powershell
npm run demo:reset
npm run demo:start
```

Проверьте, что открылся `http://localhost:5173` и на экране входа видны три кнопки быстрого входа.

## 1. Проблема и решение (30 с)

«Оперативный журнал на бумаге теряется при пересменке и плохой связи. Logbook сохраняет запись на устройстве сразу и синхронизирует её, когда сеть появится. Конфликты разбирает руководитель, а не «последний записавший».

## 2. Вход сотрудника (30 с)

Нажмите **«Сотрудник»**. В ленте три seed-записи. Обратите внимание на статусы и нижнюю навигацию.

## 3. Офлайн-запись (2 мин)

1. Откройте DevTools → **Network → Offline**.
2. Нажмите **«+ Запись»**.
3. Текст: «Осмотрел оборудование на участке, замечаний нет».
4. Тип работ: **Осмотр**; объект: **Полевой объект**.
5. **Сохранить запись**.
6. Покажите карточку: статус **«Ожидает»**, запись уже в локальном журнале.
7. Верните **Online**.
8. Откройте **«Синхронизация»** → **«Синхронизировать»**.

Ожидаемо: операция уходит, статус становится **«Синхронизировано»**.

## 4. Проверка руководителем (1 мин)

1. Выйдите.
2. Войдите **«Руководитель»**.
3. Откройте запись сотрудника.
4. Нажмите **«Проверить»**.

Ожидаемо: бейдж «Проверена», в истории — ревизия/аудит.

## 5. Конфликт (1,5 мин)

1. Выйдите и войдите **«Сотрудник»**.
2. Откройте проверенную запись → **«Изменить»** → измените текст → сохраните.
3. Перейдите в **«Конфликты»**.

Ожидаемо: поле с локальным и серверным значением, кнопки «Оставить локальное / Принять серверное / Разобрать вручную». Сервер не перезаписывает проверенную запись молча.

## 6. Наряды и аудит (1 мин)

1. **«Наряды»** — три seed-наряда; PDF отключён до OQ-03.
2. Войдите **«Администратор»** → **«Синхронизация»**: очередь, конфликты, последняя синхронизация.
3. При наличии времени: `npm run demo:permits` — CSV-импорт идемпотентен.

## 7. Честное ограничение (30 с)

«Это MVP для контролируемого внутреннего пилота: PGlite/dev-auth, ASR выключен, production-гейты G1–G3 и OIDC ещё не закрыты. Поэтому мы показываем механику, а не выдаём её за production».

## Если что-то пошло не так

- API не отвечает: проверьте окно `npm run dev:api`, `http://localhost:3001/v1/health`.
- Web не открылся: `npm run dev:web`, порт `5173`.
- Хотите чистые данные: `npm run demo:reset` и перезапуск.
- Конфликт не появился: убедитесь, что запись была **проверена** до правки.
