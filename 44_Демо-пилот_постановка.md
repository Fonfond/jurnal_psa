## 3. Что осталось до демо

### Блокеры демо

1. **S5 — корпоративный контур:** получить Linux-сервер/VM, домен, TLS, Docker Compose, PostgreSQL, backup-политику; развернуть и проверить с телефона заказчика.
2. **A2 — локальные учётные записи:** реализовано создание пользователя с паролем в админке; нужен первый admin/bootstrap и проверка входа на корпоративном стенде.
3. **A12 — передача:** указать точную дату и ФИО получателя (сейчас плейсхолдеры).
4. **S6 — Web Speech:** либо оставить «ручной ввод» как честный fallback, либо реализовать Web Speech до демо (требует интернет/разрешение микрофона).
5. **Телефон/устройства:** Android 10+/iOS 15+ — нужны физические устройства заказчика; в текущем окружении проверен только desktop Chromium.
6. **S2 — данные для демо:** нужны объект/наряд/записи, на которых показывать фильтры; иначе сценарий будет на seed-данных.

## 4. Ограничения демо (C1–C7)

- C1: не production; release FAIL / not approved.
- C2: юридически значимой ЭП нет; `simple/none` — только целостность.
- C3: on-device ASR не включён.
- C4: p99 ~2,5 с — принятый риск демо, не критерий.
- C5: iOS/квоты/вытеснение IndexedDB не проверены на устройствах.
- C6: Linux/nginx/systemd runtime и пентест не пройдены на контуре заказчика.
- C7: seed-пароли/dev-вход — только демо-стенд, не реальные данные.

## 5. Передача прав (D1–D4)

- D1: до 25.05.2027 администратор и владелец решений — Пермяков С.А.
- D2: с 26.05.2027 права передаются начальнику/энергетику УЭЭК приказом/актом; **ФИО и точная дата — уточнить**.
- D3: после передачи — технический консультант/разработчик.
- D4: B1–B8 остаются открытыми до подписания владельцами.

## 6. Критерий успеха демо

Не KPI оперативности, а:

- S1–S7 показаны без блокирующих ошибок;
- данные размещены на корпоративном контуре;
- бумага остаётся основным источником;
- заказчик дал обратную связь и решение по B1–B8;
- production-статус **не повышается** до отдельного решения о внедрении.
