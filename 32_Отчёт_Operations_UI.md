## 1. Итог

Операционные экраны перестали быть изолированными: смены, переключения и заземления теперь связаны с журналом (S-02) и карточкой записи (S-05), а состояние ЭП и офлайн-очереди видно прямо в интерфейсе.

1. **Офлайн-статусы.** На S-15 и S-16 добавлена единая панель `OfflineStatusBar`: сколько изменений ждёт отправки, сколько операций с ошибкой и конфликтов, когда была последняя успешная синхронизация, кнопка «Синхронизировать»; в офлайне — честная формулировка «изменения сохранены на устройстве». Карточка записи (S-05) показывает компактный вариант и предупреждение «запись ещё не синхронизирована — проверка и подпись недоступны».
2. **ЭП-подсказки (OQ-04).** Новый компонент `SignatureHint` читает `signature` из `/v1/me` (провайдер, алгоритм, автоподпись, legal_note) и объясняет: `none` — документ не подписывается; `simple` — целостность, но **не КЭП**; `qualified` — подпись через сервис КЭП. Подсказки на S-14 (виза), S-15 (сдача/приёмка смены), S-05 (проверка записи). Компонент `SignatureBadge`/`SignatureList` показывает реальные подписи: вид, алгоритм, время, сертификат/ключ, hash, статус.
3. **Интеграция S-02 ↔ S-15 ↔ S-16.**
   * S-02 читает `?shift_id=` и показывает баннер «Записи смены» (дата, окно, статус, ссылки «К сменам»/«Сбросить»), фильтрует записи по журналу и окну смены; `?event_type=` и селектор «Событие» фильтруют переключения/заземления; статусы событий вынесены в бейджи (Переключение, Заземление, Инцидент…), в шапке — ссылка на реестр заземлений.
   * S-15: карточка смены получила ссылку «Записи смены» → `/?shift_id=<id>`, подписи смены (если сервер вернул) и сообщение «подписи появятся после синхронизации»; ЭП-подсказка в форме сдачи и при приёмке.
   * S-16: строка реестра теперь ведёт в исходную запись журнала (`Открыть` → `/entries/<id>`), из шапки — «События заземлений» → `/?event_type=grounding`, панель офлайн-очереди, в печатной форме — фактический `legal_note` ЭП вместо заглушки.
   * S-05: событие показывается бейджем и структурированным `EventDetails` (t5), добавлены переходы «Реестр заземлений» / «Все переключения журнала», контекст смены (статус + ссылка), подписи записи из ответа сервера, кнопка «Подписать визу» (ручная подпись через `POST /entries/{id}/sign`) и офлайн-предупреждение.
4. **S-14 «Визы».** Форма и список получили ЭП-подсказку, честное сообщение об онлайн-режиме («без сети визу зафиксировать нельзя — JRN-08»), действие «Подписать визу» (`POST /journal/reviews/{id}/sign`) и загрузку подписей (`GET /journal/reviews/{id}/signatures`); после создания визы показывается подпись, если сервер её сформировал автоматически.
5. **Клиент API.** Добавлены `signEntry`, `signReview`, `reviewSignatures`; `entry()` типизирован с `signatures`, `verify()` — с `signature`, `createReview()` — с `signature`; тип `SignatureInfo` вынесен в `api/types.ts`, auth-store хранит `signature`/`features` из `/v1/me` (в т.ч. после `login`).

## 3. Поведение и ограничения

| Сценарий | Поведение |
|---|---|
| Офлайн, смена сдана | Запись и подписи появляются после синхронизации; S-15 показывает «изменения сохранены на устройстве», подписи — «появятся после синхронизации» |
| Офлайн, проверка записи | Кнопки «Проверить»/«Подписать визу»/«Снять проверку» заблокированы, S-05 объясняет причину; локальная запись доступна |
| `SIGNATURE_PROVIDER=none` | S-14/S-15/S-05 показывают «ЭП не настроена»; действия не блокируются (журнал работает), но ЭП-кнопка подписи скрыта |
| `simple` | Подпись создаётся, интерфейс явно пишет «не является КЭП (OQ-04)»; в печати — legal_note |
| `qualified` | Показывается «Квалифицированная ЭП» и алгоритм; сертификат/серийный номер — в `SignatureBadge` |
| iOS/офлайн PWA | S-15/S-16/S-05 работают из IndexedDB; фоновая отправка — см. t10 (честное сообщение на S-10) |
| Конфликт смены | S-15 показывает причину и «Сверить с сервером» (t4); офлайн-панель ведёт в конфликты/S-10 |
| Виза офлайн | Создание визы недоступно (JRN-08), кнопка disabled и сообщение; список последних виз — из кэша |

Ограничения: подписи визы/записи требуют сети (серверная подпись), офлайн-визы — JRN-08; юридическая значимость форм — OQ-04/903н; «ЭП-подсказка» отражает настройку сервера, но не заменяет проверку КЭП на стороне клиента (провайдер `qualified` — внешний сервис).

* Уведомления руководителю о сменах/конфликтах (C-09) — отдельная работа.
