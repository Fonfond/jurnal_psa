## 1. Итог

**Релиз не принят.** Основные проверки прошли, но несколько P0/P1-критериев `24` §7 остаются открытыми или подтверждены только на уровне кода/моков:

- OQ-04 (юридическая ЭП/КЭП) не закрыт; `simple` — HMAC, а не КЭП; `qualified` проверен контрактным тестовым провайдером (t25), реальный сервис КЭП не подключён;
- OQ-02 (реальный IdP/MFA) не интегрирован; OIDC/MFA проверены harness'ом по реальному HTTP (t25), credentials заказчика отсутствуют;
- AUTH-03 (локальная разблокировка/PIN, восстановление офлайн-сессии после reload) не реализован;
- AUTH-04/AUTH-05 (rate limit, idle-timeout, CSP/HSTS) реализованы и покрыты тестами (t22), nginx-конфиг проверен `nginx -t`; runtime на реальном Linux ещё не принят;
- retention scheduler/алерты/TTL реализованы (t24, 0017); сроки OQ-05/OQ-18 не утверждены;
- cold-load без ANALYZE давал changes p95 837.7/612.1 и push 421.8/419.1 (fail); t30 сделал ANALYZE обязательным, после ANALYZE p95 139.2/350.1 и 358.3 на чистой установке (pass);
- G1 fail, G2 partial (iOS/квоты/вытеснение);
- pentest, a11y и браузерный E2E не выполнены;
- `npm audit` — 0 high/critical; 3 moderate только в dev/build Workbox (waiver `docs/security/SCA_WAIVER.md`), zod/react-router обновлены;
- async audit-writer не атомарен с бизнес-транзакцией; возможна потеря audit-события при аварии; `journal_seq` может иметь разрывы при полном откате;
- Docker/Linux production-профиль не прогнан; приёмка выполнена на Windows + портативном PG 15.15.

При этом **основные инженерные проверки прошли**: 306 тестов, typecheck, build, чистая PG-установка (14 миграций на t15; текущая схема 0001–0017), production-env fail-closed, push/mixed нагрузка на t15, backup/restore (после исправления проверки под 0014), документы 35/36.

**Итоговая формулировка:** `NOT PASS` для production; `PASS WITH WAIVERS` для ограниченного внутреннего пилота в ручном режиме — только после подписания перечисленных ниже waivers владельцами.
