## 1. Блокеры (внешние, не код)

| ID | Блокер | Что нужно | Влияние | Владелец |
|---|---|---|---|---|
| B-REP01 | Нет аккредитованного сервиса КЭП/УЦ и сертификатов подписи | endpoint, token, сертификаты, договор, регламент проверки | `SIGNATURE_PROVIDER=qualified` нельзя включать в production; юридическая значимость не подтверждена (OQ-04) | Заказчик + ИБ |
| B-REP02 | Нет реального OIDC IdP и MFA-политики | issuer, client_id/secret, redirect URIs, MFA для admin, JWKS/acr/amr | production-вход заблокирован (OQ-02); доступен только dev-провайдер локально | ИТ/ИБ заказчика |
| B-REP02b | Нет маппинга групп/ролей IdP → роли Logbook | соглашение о claims/группах и владельце провижининга | роли назначаются администратором Logbook, не IdP | Заказчик |

## 2. Что уже проверено и не является mock-выдачей

- **Qualified ЭП:** HTTP-контракт `sign/verify` реализован и проверен тестовым
  HTTP-провайдером (успех, tamper, HTTP 503, invalid JSON, timeout, `E-SIG-02`
  при недоступности). Это контрактный тест транспорта, **не КЭП**; тестовый
  провайдер не включается в production.
- **OIDC/MFA:** интеграционный harness работает по реальному HTTP
  (discovery/authorize/token/JWKS), проверены redirect URI, PKCE, state/nonce,
  MFA (`acr`/`amr`) для admin, отказ `E-OIDC-04` без MFA, `E-OIDC-02` при
  недоступном token endpoint. Harness — тестовый IdP, **не production IdP**.

## 3. Условия включения в production

1. Письменное решение OQ-04 (простая ЭП / КЭП / гибрид) и договор с УЦ.
2. Предоставленные credentials/endpoint КЭП; успешный интеграционный тест с
   реальным провайдером и хотя бы одной подписью/проверкой.
3. Метаданные реального IdP (OQ-02), регистрация redirect URI, MFA-политика admin;
   успешный вход admin с MFA и worker без MFA на стенде.
4. Обновление `REP-01_02`-статуса в релизном чек-листе (t15) и снятие waiver.

## 4. Компенсации до снятия блокеров

- Production-конфигурация `env.ts` запрещает dev-вход и требует OIDC/MFA;
  `SIGNATURE_PROVIDER=qualified` без endpoint/token не стартует.
- В production не включается `SIGNATURE_PROVIDER=qualified` и не выдаётся за
  рабочую КЭП; допускается `simple` (не КЭП) только с явной оговоркой OQ-04 или
  `none`.
- Тестовые провайдеры находятся только в `apps/api/test/**` и не собираются в
  production-артефакт (`tsconfig.build` исключает тесты).
- Аудит фиксирует все ручные подписи/проверки; при недоступном КЭП подпись не
  создаётся (`E-SIG-02`).
